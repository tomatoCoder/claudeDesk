# 浏览器选中文本注释设计

## 目标与范围

在 Claude Desk 侧边栏加入“浏览器”入口，并提供 `Cmd/Ctrl+T` 快捷键。用户输入 `http` 或 `https` 地址后，应用打开或复用一个原生浏览器窗口。用户在网页中选中文本时，可在选区附近输入注释；提交后，当前 Claude 会话的输入框自动追加网址、选中文本和注释。

本功能只负责把评论作为草稿写入当前会话，不会自动发送消息，也不保存网页评论、抓取页面内容或修改网页。

## 方案选择

采用独立的原生 Tauri WebView 窗口承载远程网页，而不使用主界面的 `iframe`。这样避免常见网站以嵌入策略拒绝加载，同时使外部网页与应用主界面隔离。

浏览器窗口只被授予一个窄的 `browser_comment` IPC 命令；该命令只校验并转发文本负载到主窗口。外部网页没有项目文件读写、任务执行、Shell、对话框或其他应用命令权限。主窗口仍使用现有 `default` capability。

## 用户流程

1. 侧边栏新增“浏览器”行；点击它或按 `Cmd+T`（Windows/Linux 为 `Ctrl+T`）打开网址输入框。
2. 用户输入地址并确认。缺少协议时默认补为 `https://`；仅接受 `http://` 与 `https://`。
3. 应用创建或复用标签固定为 `browser` 的原生浏览器窗口，并导航到该地址。
4. 用户选中网页中的可见文本。注入在网页中的轻量脚本展示紧贴选区的评论输入条：取消、文本输入和“评论”提交按钮。
5. 提交后，浏览器窗口调用受限的 `browser_comment` 命令。后端校验 URL、选中文本和评论长度后，只向 `main` 窗口发出浏览器评论事件。
6. 主窗口监听该事件；存在当前任务时调用现有 `ConversationView.insertDraft`，以追加方式写入：

   ~~~text
   请处理网页评论：<comment>

   网址：<url>

   选中文本：
   ```
   <selection>
   ```
   ~~~

   没有已选会话时，不保留或发送评论，并在主窗口显示“请先选择会话”。

## 前端边界

### 主窗口

- `AppSidebar` 增加浏览器按钮与 `open-browser` 事件。
- `App.vue` 管理一个轻量地址输入对话框、快捷键、浏览器打开调用及浏览器评论事件监听。
- 新建 `browserShortcut` 和 `browserUrl` 服务，分别负责快捷键判定、URL 规范化与格式化草稿。地址输入、设置对话框或其他 modal 获取焦点时，快捷键不触发。
- 草稿使用 `ConversationView.insertDraft`，以保证行为与当前文件评论一致：追加到现有输入内容，不自动提交。

### 原生浏览器窗口

- Rust 层创建或获取固定标签 `browser` 的 `WebviewWindow`，设置合理的默认尺寸并载入远程 URL。
- 每次导航完成后注入选择与评论脚本。脚本仅在用户有非空文字选区时显示输入条；点击取消、按 `Escape` 或切换选区时关闭；点击提交或按 `Cmd/Ctrl+Enter` 发送。
- 注释控件采用 Shadow DOM、内联样式和高层级定位，减少宿主网页 CSS 对其影响。控件只读取当前 `location.href` 和当前选区文本。
- 浏览器窗口按单例复用：后续网址会导航现有窗口并置前，而不是持续创建新窗口。

## 后端与安全边界

- 新增 `commands::browser`：
  - `open_browser(url)` 仅接收规范化的 `http/https` 地址，创建或导航浏览器窗口；
  - `browser_comment(payload)` 对 URL、选中文本、评论做非空与长度校验，将安全的结构化事件发给 `main` 窗口。
- 新增 `capabilities/browser.json`，仅匹配标签 `browser`，并且仅允许调用 `browser_comment`。不包含 `core:default`、dialog、shell、files、task 或 project 命令。
- 远程来源规则仅覆盖 `http` 与 `https` 页面以支持用户输入的任意公开网址；由于网页能调用的唯一应用接口是无副作用的评论上报，其负载永远被视为不可信文本。
- `browser_comment` 不读取、写入、执行或打开系统资源；它只能导致主窗口尝试插入一段用户可见草稿。主窗口仍要求存在当前任务才消费事件。
- 地址和评论上限在前后端一致：地址最多 4096 字符，选中文本最多 20,000 字符，评论最多 4,000 字符。超限、空值、非 HTTP(S) 协议和无效 URL 都会拒绝，并以用户可理解的错误反馈。

## 错误处理

- 空地址或非法协议：地址输入框内提示，不创建窗口。
- 导航失败：浏览器窗口保留，显示浏览器运行时的加载失败页面；用户可通过侧边栏重新输入地址。
- 浏览器注入失败、远程页面阻止脚本或选区不可读：不影响浏览网页；不展示或关闭评论条。
- 主窗口未选择会话：评论不会丢进错误的任务；主窗口显示明确提示。
- 删除、退格和普通输入只由评论输入控件处理，绝不映射为浏览器窗口或文件抽屉的关闭动作。

## 测试与验收

- `browserUrl` 单测：协议补全、HTTP(S) 接受、空值/`file:`/自定义协议拒绝、长度限制。
- 快捷键单测：macOS `Meta+T`、其他平台 `Ctrl+T`、输入框/modal 阻断。
- 侧边栏与 `App.vue` 组件测试：入口发出事件、地址确认调用打开命令、浏览器评论按“网址 + 选中文本 + 评论”格式追加草稿、没有当前任务时提示。
- Rust 单测：URL 与评论 payload 校验；浏览器窗口单例的创建/复用逻辑提取成可测纯函数或以窗口管理接口覆盖。
- capability 配置检查：浏览器 capability 不获得现有 `default` 权限或任何文件、Shell、任务命令。
- 回归：现有文件选择、评论、编辑与 Delete/Backspace 输入测试仍通过；构建通过。

## 非目标

- 不提供多标签、历史、书签、下载、开发者工具或持久化网页评论。
- 不自动将整页内容、cookie、登录信息或网页脚本传入 Claude 会话。
- 不绕过网站认证、同源策略或内容安全策略。
