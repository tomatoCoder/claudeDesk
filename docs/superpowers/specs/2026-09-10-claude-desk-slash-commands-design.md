# Claude Desk 斜杠命令与 Skill 对齐设计

**日期：** 2026-09-10

**状态：** 已在对话中确认

**目标：** 让 Claude Desk 的 `/` 命令发现、Skill 调用和 CLI 内置命令行为尽可能与用户当前安装的 Claude CLI 保持一致。

## 1. 背景与问题

Claude Desk 目前将输入框内的文本原样作为 `run.start` 提示词交给 Agent Bridge，但没有命令发现、斜杠补全、CLI 本地命令输出或交互命令的专用界面。用户无法在 App 中看到当前项目实际可用的 Skill，也不能可靠地使用 `/help`、`/model`、`/config`、`/permissions` 等 CLI 内置命令。

命令列表不应由 Claude Desk 扫描目录或手工维护。Claude CLI 会根据用户、项目、本地设置、插件和当前工作目录组合出最终能力，只有 CLI/Agent SDK 能作为这一列表的真实来源。

## 2. 已确认的产品决策

- 输入 `/` 后在输入框上方显示命令面板。
- 列表包含当前项目的 Skill 与 CLI 内置斜杠命令，而不是仅支持 Skill。
- 列表、描述、参数提示和别名以 Agent SDK 的 `supportedCommands()` 结果为唯一真实来源。
- “与 CLI 一致”的可验证边界，是当前 CLI 在 Agent SDK 模式下通过 `supportedCommands()` 公开的完整目录；只存在于交互终端内部、未通过 SDK 暴露的私有命令不硬编码补齐，而是作为版本兼容限制记录。
- Skill 和可直接执行的命令保持原文交给 CLI，Claude Desk 不自行展开 Skill 内容。
- 需要选择器或配置界面的 CLI 命令在 Claude Desk 中使用原生弹窗或面板，不嵌入终端。
- CLI 已公开但当前 Agent SDK 没有结构化交互接口的命令仍显示在目录中；执行时显示明确的兼容说明，不伪造成功结果，也不依赖 CLI 私有内部文件。
- 普通聊天不依赖命令目录成功加载。

## 3. 范围

### 3.1 包含

- 按项目从 CLI/SDK 读取命令目录。
- `/` 命令面板、搜索、别名匹配、参数提示和键盘导航。
- 将 Skill 和非交互命令原样交给 CLI 执行。
- 展示 SDK `local_command_output` 消息。
- 处理 SDK `commands_changed` 通知并失效项目缓存。
- 交互命令适配器框架，以及当前 CLI 目录中能通过稳定 SDK 接口实现的内置命令适配器。
- `/help`、`/model`、`/config` 和 `/permissions` 作为首要冒烟用例。
- 目录加载、执行和兼容错误状态。

### 3.2 不包含

- 嵌入 PTY 或终端模拟器。
- 通过解析 CLI 彩色终端输出重建交互界面。
- 扫描 `~/.claude/skills`、`.claude/skills` 或插件目录来猜测可用命令。
- 在前端硬编码一份可能与 CLI 版本漂移的命令列表。
- 在 SDK 未公开安全写入契约时直接改写 CLI 私有状态。

## 4. 架构

```text
ComposerBox 命令面板 / 原生命令面板
                    |
                 Tauri IPC
                    |
          Rust 命令目录缓存
                    |
              Bridge 协议
                    |
  Agent SDK supportedCommands / query / control API
                    |
             用户的 Claude CLI
```

### 4.1 Agent Bridge

Bridge 协议新增短生命周期的 `commands.list` 请求。请求至少包含经 Rust 层验证的绝对 `claudePath` 和项目 `cwd`；如果查询与已有会话绑定，可携带 `sessionId`。

Bridge 使用与真实轮次相同的 SDK 设置：

- `cwd` 为项目路径；
- `pathToClaudeCodeExecutable` 为已验证的本机 CLI；
- `settingSources` 为 `user`、`project`、`local`；
- 不使用 SDK 自带的另一个 CLI 版本。

初始化后读取 `supportedCommands()`，标准化为可序列化的命令数组。无论成功、超时、取消或异常，都必须关闭该 SDK query 和子进程。

现有 `run.start` 保持原始提示词，不在 Bridge 中重新解析 Skill。消息标准化增加：

- `local_command_output` → 可在时间线展示的本地命令输出；
- `commands_changed` → 覆盖语义的最新命令目录通知。

### 4.2 Rust/Tauri 核心

Rust 层新增 `list_slash_commands(project_id, task_id?)` IPC，负责：

1. 通过已存在的项目索引解析项目，不接受前端任意传入的工作目录。
2. 使用已诊断的 Claude CLI 路径发起 Bridge 请求。
3. 将 Bridge 命令转为 `SlashCommandDto`。
4. 按规范化项目路径与 CLI 版本做进程内缓存。
5. 收到 `commands_changed`、CLI 路径/版本变化或用户主动重试时失效对应缓存。

命令目录不写入 SQLite，因为它依赖当前文件系统和 CLI 版本，持久化会导致过期命令。

### 4.3 Vue 前端

前端增加一个按项目管理的命令状态，但命令目录本身不进入全局持久化设置。`ConversationView` 在项目/会话可用且 CLI 就绪后请求目录，并将当前列表传给 `ComposerBox`。

`ComposerBox` 仅在光标所在的首个 token 以 `/` 开头时打开面板。搜索对名称和别名做不区分大小写的前缀匹配，名称匹配优先于别名匹配。每项展示：

- `/<name>`；
- CLI 返回的描述；
- 可选的参数提示；
- 适用时显示别名。

键盘行为与 CLI 命令补全习惯保持一致：

- `ArrowUp` / `ArrowDown` 移动选中项；
- `Enter` 或 `Tab` 填入命令；
- `Escape` 关闭面板；
- 点击命令与键盘选择相同；
- 选择只填入 `/<name>` 和必要的后置空格，不自动提交。

面板使用 `listbox`/`option` 语义、明确的活动项和焦点管理。命令面板打开时，输入焦点仍保持在 textarea。

## 5. 命令路由与交互适配

### 5.1 命令数据契约

```ts
interface SlashCommandDto {
  name: string
  description: string
  argumentHint: string
  aliases: string[]
}
```

名称不含前导 `/`。Bridge 要拒绝空名称，并将缺失的描述、参数提示或别名标准化为空值；不对 CLI 返回的文案做本地化改写。

### 5.2 路由顺序

用户提交以 `/` 开头的输入时：

1. 如果命令有已注册的原生交互适配器，打开对应面板。
2. 否则保持输入原文，经现有 `sendTurn`/`run.start` 路径交给 CLI。
3. CLI 负责解析 Skill、别名、参数、插件命令与本地命令。
4. 输出以普通助手消息或本地命令输出显示在时间线。

不应在前端先将别名改写为主命令；别名解析仍由 CLI 执行，以保留 CLI 原生错误和钩子行为。

### 5.3 原生适配器

适配器具有稳定的前端契约：是否接管命令、加载面板数据、提交选择、取消、以及将 CLI/SDK 错误转为用户可理解的结果。适配器只可使用公开 SDK 控制接口或现有 Tauri 安全设置 API。

首要适配行为：

- `/help`：如果 CLI 以 `local_command_output` 返回文本，直接在会话中展示。
- `/model`：使用 SDK 可用模型数据打开原生单选面板，选定后交由 CLI/SDK 更新，不在前端伪造会话模型。
- `/config`：打开原生配置面板。仅展示和修改当前 SDK 或 Tauri 已有安全存储契约可支持的设置项；其他项显示版本兼容说明。
- `/permissions`：复用现有权限类型和安全边界，显示当前可管理的规则/授权；永不因界面无法表达某条 CLI 策略而自动放宽权限。

对于命令目录中的其他内置命令，无需交互面板的命令默认直接交给 CLI。如果命令需要 SDK 未提供的终端专用交互，使用统一的“当前 CLI/SDK 组合暂不支持在桌面端完成此交互”状态，并保留普通输入内容以便用户编辑。

## 6. 运行时数据流

### 6.1 加载命令目录

1. 用户打开项目或会话。
2. `ConversationView` 请求当前项目命令目录。
3. Rust 先检查内存缓存；未命中时启动 Bridge 目录请求。
4. Bridge 初始化 SDK，读取 `supportedCommands()`，序列化结果并关闭临时进程。
5. Rust 验证返回值后缓存并返回前端。
6. 用户输入 `/` 时使用已加载列表；若列表仍在加载，面板显示轻量加载状态。

### 6.2 执行 Skill

1. 用户选择 Skill，输入框被填入 `/skill-name `。
2. 用户补充参数并提交。
3. 文本原样经 `sendTurn` 传到 Agent Bridge。
4. CLI 按当前项目、设置源和插件状态解析并展开 Skill。
5. 后续的模型、工具、权限和流式输出沿用当前轮次数据流。

### 6.3 执行交互命令

1. 提交前路由器识别已注册适配器。
2. 适配器通过 Tauri IPC 加载 SDK/CLI 已公开的实际状态。
3. 用户在原生面板中确认选择。
4. 适配器调用对应控制或设置 API；只有 CLI/SDK 确认成功后才更新界面状态。
5. 取消面板不发生外部变更，输入草稿保留。

## 7. 错误处理

- CLI 不可用：不发起目录请求，继续复用现有 CLI 诊断引导。
- 目录初始化超时：终止临时进程，显示重试操作，不禁用普通文本发送。
- SDK 返回畸形命令：丢弃该项并记录不含敏感数据的诊断信息；其他项继续可用。
- 命令在列表加载后被移除：仍将用户提交的原文交给 CLI，展示 CLI 的真实未知命令错误。
- 适配器发现 SDK 版本不支持所需能力：不尝试写入，显示 CLI 版本、SDK 版本和可采取的替代操作。
- 命令执行失败：沿用时间线错误卡和现有关联 ID，不将错误误标为普通助手回复。
- 项目切换竞态：请求结果必须携带项目 ID；前端只采用与当前项目一致的结果。

## 8. 安全与兼容性

- 项目路径和 CLI 路径继续由 Rust 层验证，前端不能借命令目录请求启动任意程序。
- 命令描述视为不可信文本，Vue 仅做普通文本渲染，不执行 HTML。
- 用户输入的参数不经 shell 插值，只通过已有 JSON 协议传递给 Agent SDK。
- 原生交互命令不得绕过现有权限请求、取消或应用退出边界。
- 可用命令集以运行时能力检测为准，不以 Claude Desk 编译时的 CLI 版本为准。
- 新 CLI 命令会自动出现在面板中；新的交互语义在有稳定 SDK 契约前使用显式兼容状态。
- 每次目录请求都记录 CLI 与 SDK 版本到非敏感诊断上下文，便于区分“命令不存在”与“当前组合未公开该命令”，但不得记录用户参数或命令输出。

## 9. 测试与验收

### 9.1 前端测试

- 只输入 `/` 时展示完整列表。
- 输入 `/pdf` 时按名称和别名过滤，名称前缀匹配优先。
- 上下键、Enter、Tab、Escape 和鼠标点击符合定义的补全行为。
- 选择命令不自动提交，不丢失参数草稿。
- 加载与错误状态不阻断普通输入。
- 项目切换后不会采用上一项目的延迟结果。
- 原生命令面板的确认、取消、焦点恢复和错误显示均有组件测试。

### 9.2 Bridge 与 Rust 测试

- `commands.list` 协议解析、绝对路径验证和结果标准化。
- 目录 SDK query 在成功、超时、取消和异常路径都被关闭。
- `local_command_output` 和 `commands_changed` 的事件映射。
- Rust IPC 只能为已建立索引的项目发起查询。
- 缓存按项目和 CLI 版本隔离，并在能力变化事件后失效。
- 命令参数原文经 JSON 协议传递，没有 shell 再解析。

### 9.3 本机冒烟测试

在已认证的本机 Claude CLI 上验证：

1. 用户级 Skill 出现在任意项目，项目级 Skill 只出现在对应项目。
2. 选择一个 Skill，填入参数并成功执行。
3. `/help` 在会话中显示 CLI 返回的本地输出。
4. `/model` 面板显示 SDK 提供的模型并在 CLI 确认后更新。
5. `/config` 只允许安全契约已支持的设置项实际写入。
6. `/permissions` 不会降低现有权限约束，取消时没有状态变更。
7. CLI 不可用、目录超时与 SDK 缺少能力时出现正确的降级界面。

### 9.4 完成标准

- 命令面板的内容与当前项目 CLI/SDK 返回的目录一致。
- 对比验收以同一项目、同一 CLI 可执行文件、同一设置源下的 `supportedCommands()` 原始结果为基准；不承诺枚举 SDK 未公开的终端私有命令。
- Skill 名称、参数和执行语义不被 Claude Desk 改写。
- 可直接执行的 CLI 内置命令能正确展示结果。
- 有稳定结构化能力的交互命令使用原生界面完成真实操作。
- SDK 无法承接的 CLI 专用交互显示可诊断的兼容状态，不假定已成功。
- 命令目录失败不会回归普通聊天、多会话并发、停止任务或工具授权流程。

## 10. 与应用 Logo 改动的关系

应用 Logo 替换是独立的已实现改动，不是本功能的依赖。斜杠命令实现不应回退侧边栏 Logo、favicon 或 Tauri 平台图标；最终验证时两组改动共同运行全量测试与构建。
